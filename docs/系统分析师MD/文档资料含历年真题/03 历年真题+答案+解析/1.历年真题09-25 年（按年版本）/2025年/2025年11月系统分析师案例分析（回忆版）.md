1.案例一在某销售管理系统的建设项目中，由于系统业务功能复杂，项目组在需求获取阶段决定针对不同类型的需求采用不同的需求获取方法。项目组可选择的需求获取方法包括：用户访谈、联合需求计划（JRP）、问卷调查、文档分析和实地观察。1. 为确保全面准确获取用户需求，项目组提出以下需求获取目标：2. 获取现有销售管理系统中已实现的实体店销售模式和业务过程；3. 获取系统改进需求及用户期望新增的业务功能；4. 了解当前业务过程的详细数据及这些数据背后的业务原因；5. 从企业管理层、销售人员、业务文档等多种来源尽可能广泛地获取需求信息；6. 解决需求冲突，使需求尽可能全面、一致；7. 提高用户参与度，让更多用户参与需求获取过程。【问题 1】（6 分）请用约 300 字说明以下三类需求的含义：业务需求、用户需求和系统需求。请回答第1个问题

答案：【问题1】业务需求描述企业层面的业务目标、业务流程、管理策略等，是“企业想达到什么目标”。它关注的是组织层面的价值，业务需求不涉及系统如何实现，而强调业务问题和业务痛点。用户需求是指不同类型用户（管理人员、销售人员、客服等）在实际工作中对系统提出的希望和需求，描述“用户需要系统提供什么”。用户需求侧重功能性诉求，是业务需求的进一步细化。系统需求是根据用户需求和业务需求分析得出的对系统功能、性能、接口、安全等方面的详细规定，是“系统应当怎样实现”。包括功能需求、非功能需求（如性能、可靠性、兼容性）等。系统需求具有可验证性，是系统设计与开发的直接依据。

4.试题二在某电商平台“双十二”大促期间，系统出现以下性能问题：1. 数据库 CPU 使用率超过 95%，大量请求直接打到数据库，造成性能瓶颈。2. 热点商品缓存频繁失效，导致请求绕过缓存访问数据库，出现缓存击穿。3. 恶意用户频繁请求“不存在的商品 ID”，导致缓存层无法命中，直接穿透至数据库，造成缓存穿透问题。为解决上述问题，系统提出以下优化方案：• 引入 Redis 集群 实现读写分离，并采用 哨兵模式保证高可用；• 使用 布隆过滤器（Bloom Filter） 拦截不存在的商品 ID，防止缓存穿透；• 使用 Write-Through 策略进行缓存与数据库主从同步，保证数据一致性。【问题 1】（8 分）与 Memcached 相比，Redis 的两个主要优势是什么？为什么布隆过滤器可以有效防止缓存穿透？请说明其原理。请回答第1个问题

答案：【问题 1】（8 分）1. Redis 相比 Memcached 的两个优势（写任意两点即可得分）① 数据类型丰富Redis 支持字符串、列表、集合、有序集合、哈希、HyperLogLog、位图等，Memcached 仅支持简单 Key-Value 字符串。② 持久化支持Redis 提供 RDB、AOF 持久化，服务重启后仍能恢复数据；Memcached 不支持持久化。（以下作为补充点也可写）✓ Redis 支持 Lua、事务、发布订阅✓ Redis 单线程但更稳定，支持 LRU、本地淘汰策略更多2. 为什么布隆过滤器能防止缓存穿透？核心原理：布隆过滤器通过多个哈希函数将 key 映射到一个位数组中。当查询某个 key 时：若布隆过滤器判断 key 不存在（位数组中有 0） → 一定不存在若判断存在 → 可能存在，需要继续查缓存/数据库因此，布隆过滤器能提前拦截“必不存在的商品 ID”请求，避免它们穿透到数据库。

10.web背景题目。【问题1】前后端分离及优点请回答第1个问题

答案：【问题1】1、前后端分离的概念• 前端（Web/APP）与后端（服务端）通过 API 进行通信，双方仅通过 JSON/HTTP 交互，而不再直接耦合页面与业务逻辑。• 前端负责 UI 展示与交互，后端负责业务逻辑、数据处理与存储。• 前端与后端可 独立开发、独立部署、独立演进。2、前后端分离的主要优点• 开发效率提升：前后端并行开发，通过明确的 API 契约提高协作效率。• 架构清晰、职责分离：前端负责界面、后端负责逻辑，使系统更加解耦易维护。• 用户体验更好：前端可用 SPA 实现更流畅的页面交互与更快的响应速度。• 支持多终端复用：同一套后端 API 可服务 Web、APP、小程序等多端，减少重复开发。• 扩展与部署灵活：前后端可独立部署扩容，前端还能用 CDN 加速，后端按需伸缩。• 技术栈选择自由：前端与后端各用最合适的技术，互不影响演进升级。
